## Immediate A2 correction

The branch passed its recorded automated checks and original two code-review
delta cycles. A fresh native planning trial then failed because the subject
performed source exploration inline and never dispatched the required child.
It read the planning instructions, had the native tool available, and recorded
no skip decision. A structurally valid plan is not proof of role-policy adoption.

The proposed correction makes required exploration a prerequisite to source
exploration and handoff, with an observable native-child receipt or an explicit
blocked result. Preserve the existing narrow skip rule. Apply shared policy to
both trees, add a focused contract assertion, and validate a fresh uncoached
subject using actual tool and ledger evidence. Do not teach the subject the
grading criteria or relabel the previous failed trial.

The previous review's two-cycle allowance was exhausted. The receiving owner
must establish an explicit continuation allowance for any additional correction
cycle. A dispatch-count extension alone is not recorded approval to reset that
review history. No new whole-branch discovery is implied by this plan.

## Later integration

B2, B4, B5, and B6 share B1 but are not automatically a linear stack. Their
unit fixtures use synthetic projects, arbitrary declared media, multiple recipes,
negative requirements, and a project with no feature catalog. Their live gates
use an actual consuming project's committed recipes and owned environment.
Synthetic fixtures must not replace a named project-integration requirement.

Each consuming project maintains its own recipe/catalog identities and source
provenance. Missing live prerequisites block the corresponding acceptance leg,
not all independent repository implementation. Keep those distinctions visible
in readiness reports. Do not hardcode a consuming product into this plugin.

One complete lower PR precedes dependent implementation. Independent units stay
main-based. Only actual unmerged dependencies qualify for native stack linkage.
The human reviews and merges. Tests and review policy come from the repository
and skills, not from an additional process loop in this document.
